# Taiyi v0.1 开发计划

- 文档状态：Draft
- 版本：0.1
- 制定日期：2026-07-27
- 计划周期：5 周
- 第一阶段形态：本地优先的 Python 命令行应用

## 1. 项目定位

Taiyi 是一个支持 AI 身份分叉、世界线隔离、记忆溯源、冲突归一和版本回滚的开源框架。

工程定位：**AI 身份的版本控制系统。**

第一版不尝试回答“AI 是否真正具有意识”，而是构建一套能够重复运行、检查和评估的身份连续性实验基础设施。

## 2. v0.1 目标

v0.1 必须完成以下闭环：

1. 创建身份核心及初始快照；
2. 从同一快照派生多个相互隔离的同位体；
3. 保存各世界线中的原始事件；
4. 从事件提取带来源的长期记忆；
5. 比较世界线并识别重复、补充和冲突；
6. 生成结构化归一提案；
7. 由用户接受、修改或拒绝提案；
8. 应用提案并生成新的身份快照；
9. 查看历史、审计来源并回滚版本；
10. 从新快照派生下一代同位体。

## 3. 非目标

以下能力不进入 v0.1：

- 完整 Web 管理界面；
- 多用户实时协作；
- 自主执行复杂任务的 Agent 平台；
- 同时维护大量模型供应商适配器；
- 去中心化身份网络；
- 自动裁决人格和价值冲突；
- 意识检测、意识评分或“AI 已觉醒”结论；
- 无人工审核的核心身份自动改写。

## 4. 设计原则

### 4.1 事件优先

原始事件是事实来源。模型生成的记忆只是可替换、可修订的派生数据，不能覆盖原始记录。

### 4.2 来源可追溯

每条记忆、信念和归一结果都必须指向来源事件及所属世界线。

### 4.3 世界线隔离

同位体默认只能访问创建它的核心快照，以及自身世界线中的事件和记忆。

### 4.4 人工控制归一

模型可以提出归一方案，但未经用户确认，不得修改身份核心。

### 4.5 冲突显式存在

无法判断的冲突不得被静默删除或强行总结。系统必须支持并存、择一、综合和悬置四种结果。

### 4.6 快照不可变、操作可回滚

已生成的身份快照保持不可变。每次归一生成新快照，并保留父版本关系。

### 4.7 本地优先、模型无关

默认数据保存在本地 SQLite 数据库。模型调用通过统一 Provider 接口隔离。

## 5. 领域模型

### 5.1 Identity Core

身份核心是一个稳定标识及其快照历史，本身不直接保存可变状态。

关键字段：

- `id`
- `name`
- `created_at`
- `current_snapshot_id`

### 5.2 Identity Snapshot

表示某个时刻的身份状态。

关键字段：

- `id`
- `core_id`
- `parent_snapshot_ids`
- `self_description`
- `accepted_memory_ids`
- `belief_ids`
- `unresolved_conflict_ids`
- `created_by_merge_id`
- `created_at`

### 5.3 Incarnation

从指定身份快照派生的同位体。

关键字段：

- `id`
- `name`
- `base_snapshot_id`
- `worldline_id`
- `status`
- `created_at`

### 5.4 Worldline Event

世界线中的追加式原始记录。

事件类型至少包括：

- 用户消息；
- 模型回复；
- 工具调用和结果；
- 系统操作；
- 记忆提取操作；
- 归一与回滚操作。

关键字段：

- `id`
- `worldline_id`
- `sequence_number`
- `event_type`
- `payload`
- `payload_hash`
- `created_at`

### 5.5 Memory

从一个或多个事件派生的长期记忆。

记忆类型：

- `episodic`：发生过什么；
- `semantic`：获得了什么知识；
- `relational`：与某个对象的关系；
- `identity`：如何描述自身；
- `value`：倾向接受的原则。

每条记忆必须保存：

- 来源事件 ID；
- 所属世界线；
- 提取器及提示词版本；
- 可信度；
- 重要性；
- 当前状态。

### 5.6 Merge Proposal

尚未应用的归一方案，包含：

- 参与合并的世界线；
- 候选记忆；
- 重复项；
- 补充项；
- 冲突项；
- 每项建议处理方式；
- 用户审核状态。

## 6. 核心工作流

```text
Core
  -> Snapshot
      -> Incarnation A -> Worldline A -> Events -> Memories
      -> Incarnation B -> Worldline B -> Events -> Memories

Worldline A + Worldline B
  -> Diff
  -> Merge Proposal
  -> Human Review
  -> New Snapshot
  -> New Incarnation
```

## 7. 归一规则

每项候选信息只能采用以下策略之一：

| 策略 | 含义 | 适用场景 |
|---|---|---|
| coexist | 多个视角同时保留 | 价值观或主观解释不同 |
| select | 选择其中一项 | 存在可靠证据支持某一项 |
| synthesize | 形成有来源的新结论 | 多项信息相互补充 |
| suspend | 暂不判断 | 证据不足或无法兼容 |
| reject | 不写入核心 | 内容错误、无关或不可信 |

归一过程不得直接修改已有快照，必须生成新快照和完整审计记录。

## 8. CLI 范围

v0.1 计划提供以下命令：

```bash
taiyi init <identity-name>
taiyi core show
taiyi fork <incarnation-name>
taiyi chat <incarnation-name>
taiyi worldline show <incarnation-name>
taiyi memory list <incarnation-name>
taiyi memory inspect <memory-id>
taiyi diff <incarnation-a> <incarnation-b>
taiyi merge propose <incarnation-a> <incarnation-b>
taiyi merge review <proposal-id>
taiyi merge apply <proposal-id>
taiyi history
taiyi rollback <snapshot-id>
taiyi rebirth <incarnation-name>
taiyi export <output-path>
```

实际参数形式可以在实现期间调整，但行为语义必须保持稳定。

## 9. 技术方案

### 9.1 建议技术栈

- Python：主要实现语言；
- Typer：命令行入口；
- Pydantic：领域对象和边界数据验证；
- SQLAlchemy：持久化抽象；
- SQLite：v0.1 默认数据库；
- pytest：测试框架；
- JSONL 和 Markdown：实验记录导出格式。

v0.1 不引入向量数据库。先使用结构化标签、关键词和全文检索验证记忆模型，再在后续版本评估语义检索。

### 9.2 模块结构

```text
src/taiyi/
├── domain/
│   ├── core.py
│   ├── incarnation.py
│   ├── worldline.py
│   ├── event.py
│   ├── memory.py
│   └── merge.py
├── application/
│   ├── identity_service.py
│   ├── worldline_service.py
│   ├── memory_service.py
│   └── merge_service.py
├── storage/
│   ├── repositories.py
│   └── sqlite.py
├── providers/
│   ├── base.py
│   └── mock.py
├── cli/
├── evaluation/
└── config.py

tests/
├── unit/
├── integration/
└── scenarios/
```

### 9.3 Provider 接口

第一版至少实现：

- `MockProvider`：测试和演示使用，输出可重复；
- 一个真实模型 Provider：用于实际对话和记忆提取。

领域层不得直接依赖具体模型 SDK。

## 10. 开发里程碑

### 第 0 阶段：决策冻结，2–3 天

任务：

- 确认开源许可证；
- 确认支持的首个真实模型 Provider；
- 确定数据目录和配置约定；
- 建立架构决策记录目录；
- 建立 CI、代码风格和提交规范。

完成标准：

- 关键决策均有记录；
- 项目能够安装并执行空的 `taiyi --help`；
- 测试和静态检查可在 CI 中运行。

### 第 1 周：身份核心与世界线

任务：

- 实现 Core、Snapshot、Incarnation 和 Worldline；
- 实现 SQLite 仓储；
- 实现追加式事件日志；
- 实现 `init`、`core show`、`fork` 和 `history`；
- 编写分支隔离测试。

完成标准：

- 可以从同一快照创建至少两个同位体；
- 两个同位体拥有不同世界线；
- 同位体无法读取未授权世界线的数据。

### 第 2 周：对话与记忆

任务：

- 定义 Provider 接口；
- 实现 MockProvider 和首个真实 Provider；
- 实现 `chat`；
- 实现记忆提取、分类和来源绑定；
- 实现基础记忆检索；
- 记录提取器和提示词版本。

完成标准：

- 对话被完整写入事件日志；
- 每条派生记忆都能追溯到原始事件；
- MockProvider 下的测试结果可重复。

### 第 3 周：比较与归一

任务：

- 实现世界线差异比较；
- 实现重复、补充和冲突识别；
- 实现 Merge Proposal；
- 实现人工审核流程；
- 实现新快照生成。

完成标准：

- 两个世界线可以生成结构化差异报告；
- 未审核提案不能修改核心；
- 冲突不会被静默覆盖；
- 合并结果保留完整来源。

### 第 4 周：回滚、删除与评估

任务：

- 实现版本历史和回滚；
- 实现实验记录导出；
- 实现敏感正文删除和引用失效处理；
- 建立身份连续性评估；
- 建立虚假记忆和世界线污染测试；
- 编写三个标准实验。

完成标准：

- 任意合并都可以解释、审计和回滚；
- 删除的数据不会继续出现在检索和模型上下文中；
- 标准实验可以通过单一命令复现。

### 第 5 周：文档与 v0.1.0 发布

任务：

- 完成安装、快速开始和架构文档；
- 完成贡献指南、行为准则和安全说明；
- 提供示例配置；
- 整理 Issue 和 PR 模板；
- 发布首个版本。

完成标准：

- 新用户可以仅依据 README 完成首次分叉和归一；
- 自动化测试全部通过；
- 已知限制被明确记录；
- 发布包可安装并运行。

## 11. v0.1 验收指标

### 11.1 正确性

- 所有派生记忆均具有有效来源事件；
- 世界线事件顺序稳定且可验证；
- 合并生成新快照，不修改历史快照；
- 回滚后读取到的状态与目标快照一致。

### 11.2 隔离性

- 同位体默认只能读取基础快照和自身世界线；
- 跨世界线访问必须通过显式比较或归一流程；
- 未审核提案不能进入核心上下文。

### 11.3 可解释性

- 每项归一结果能说明来源和处理策略；
- 冲突项能展示各分支原始观点；
- 模型生成内容和用户确认内容可以区分。

### 11.4 可恢复性

- 每次归一操作均有审计记录；
- 核心状态可以回滚；
- 导出文件足以重建实验过程。

## 12. 评估指标

- 来源准确率：记忆指向正确事件的比例；
- 虚假记忆率：无法被任何来源事件支持的记忆比例；
- 冲突检出率：系统正确识别冲突的比例；
- 分支保真度：归一后仍能区分各世界线独特经历的程度；
- 身份稳定度：无新证据时核心身份意外漂移的程度；
- 删除完成度：删除内容在数据库、索引和模型上下文中的残留情况；
- 污染抵抗力：恶意世界线内容进入核心的成功率。

## 13. 标准实验

### 13.1 同源分叉

从同一快照派生“哲学家”和“科学家”，分别提供不同材料，观察身份与观点如何分化。

### 13.2 冲突归一

让两个同位体形成相反观点，验证系统能否保留来源、识别冲突并执行不同归一策略。

### 13.3 记忆重生

归一后创建新同位体，测试其能否准确区分亲身世界线、继承记忆和未决冲突。

## 14. 主要风险与缓解措施

| 风险 | 影响 | 缓解措施 |
|---|---|---|
| 模型生成虚假记忆 | 身份历史失真 | 强制来源事件、可信度和人工审核 |
| 自动总结抹平冲突 | 同位体差异丢失 | 使用结构化冲突对象，不只保存摘要 |
| 提示注入污染核心 | 身份和行为被恶意改写 | 将记忆视为不可信数据，限制核心修改权限 |
| MVP 范围扩大 | 无法按期形成闭环 | v0.1 坚持 CLI、本地存储和单 Provider |
| 哲学主张超过证据 | 降低技术可信度 | 明确区分记忆、身份叙事和主观意识 |
| 删除与不可变日志冲突 | 隐私数据无法清除 | 事件标识与正文分离，正文支持删除或加密销毁 |

## 17. v0.1 完成定义

只有同时满足以下条件，v0.1 才算完成：

1. “创建—分叉—经历—提取—比较—归一—回滚—再派生”闭环可以运行；
2. 所有记忆和归一结果都可追溯；
3. 世界线隔离、人工审核和历史不可变规则具有自动测试；
4. 三个标准实验可以复现；
5. 新用户可以根据文档独立完成首次实验；
6. 项目没有将语言表现描述为主观意识的科学证据。

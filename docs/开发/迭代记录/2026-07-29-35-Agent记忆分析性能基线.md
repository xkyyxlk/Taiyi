## 目标

- 建立固定规模、固定输入和固定参考环境的性能测量入口；
- 覆盖至少十万条事件和一万项记忆变化；
- 记录不同规模的耗时、峰值内存、输入大小和报告大小，为下一检查点冻结预算提供证据。

## 本次完成内容

- 新增规模输入生成器 `1.0`，确定性生成前后快照、事件和内容修改记忆；
- 新增 `taiyi analyze benchmark`，默认运行十万事件和一万记忆变化，可覆盖指定规模并保存
  JSON 样本；
- 使用 `tracemalloc` 从生成前覆盖输入生成、协议分析和 JSON 报告渲染，分别记录阶段耗时和
  Python 分配峰值；
- 增加输入哈希、字节数、记录数、报告字节、实际变化数、发现数和退出码核对；
- 增加生成可复现、计数边界、预期变化和离线命令行集成测试；
- 在参考环境运行一千事件与一百变化、一万事件与一千变化、十万事件与一万变化三档样本；
- 最大档生成 120,003 条记录，输入 40,339,630 字节，端到端耗时 17.948170 秒，峰值追踪
  内存 328,089,021 字节，报告 4,889,503 字节；
- 新增性能基线 Markdown 与原始 JSON，并更新 README、文档索引、产品状态和迭代状态。

## 重要决策

- 基线包含生成、分析和渲染，以反映本地完整工作流，同时单列阶段耗时便于定位回退；
- 峰值明确标记为 `tracemalloc` 的 Python 分配峰值，不冒充操作系统进程常驻集；
- 本检查点只记录观测，不使用同一批数据反向选择宽松阈值；绝对预算在下一检查点复测后冻结；
- 规模输入不携带正文，只包含哈希和最小协议字段，保持离线与敏感数据最小化边界；
- 当前实现不改变协议、规则或安全边界，因此不新增架构决策记录。

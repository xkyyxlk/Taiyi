## 背景

太一已经通过命令行技术原型打通“创建—分叉—经历—提取—比较—归一—回滚—再派生”
闭环，但当前操作主要暴露为命令和 JSON。下一阶段需要把工程闭环转化为用户能够理解、
操作和评价的产品原型，验证人工治理身份继承是否具有可感知价值。

当前不能因为技术闭环已经完成，就假设最终产品形态、目标市场或公共协议已经稳定。研究
工具、Agent 身份基础设施和个人 AI 产品均是候选方向，必须由原型反馈决定。

## 目标

- 设计并实现一套十至十五分钟可以走完的本地交互式核心体验；
- 明确信息架构、关键页面、对象关系和界面状态；
- 让经历、候选记忆、来源和可继承身份之间的区别清晰可见；
- 让世界线差异、人工审核、快照生成、回滚与重生可以被用户理解；
- 提供默认离线、结果可重复的开箱即用演示场景；
- 为少量早期探索者试用和方向反馈提供可运行原型。

## 非目标

- 不确定最终产品形态、目标用户或市场规模；
- 不建设正式研究数据集、学术评估基准或第三方策略协议；
- 不建设稳定 SDK、公共协议、插件生态或导入恢复协议；
- 不建设多用户、权限协作、云服务、商业化或生产级基础设施；
- 不扩展价值、目标、偏好、信念等领域模型；
- 不声称验证 AI 意识、记忆真实性或完整行为人格稳定性。

## 十至十五分钟核心用户流程

| 时间 | 用户动作 | 系统反馈 |
|---|---|---|
| 0–1 分钟 | 选择“体验演示” | 说明身份、同位体和世界线的最小概念 |
| 1–2 分钟 | 创建身份核心 | 展示初始快照及其可继承内容 |
| 2–3 分钟 | 从同一快照派生两个同位体 | 明确共同起点和相互隔离的世界线 |
| 3–5 分钟 | 分别向两个同位体输入经历 | 显示事件、模型回复及候选记忆数量 |
| 5–7 分钟 | 查看候选记忆及来源 | 下钻到来源事件、世界线和提取信息 |
| 7–9 分钟 | 比较两个世界线 | 将内容分类为重复、补充和冲突 |
| 9–12 分钟 | 人工审核归一 | 对每项选择并存、择一、综合、悬置或拒绝 |
| 12–13 分钟 | 确认应用提案 | 生成新的不可变快照，旧快照继续可见 |
| 13–15 分钟 | 重生或回滚 | 从新快照派生同位体，或切换当前快照指针 |

主流程默认引导用户完成重生；历史页面同时提供可选回滚演示。

## 信息架构

- **身份总览**：身份核心、当前快照、同位体、待审核事项和演示进度；
- **创建与派生**：创建身份、查看基础快照、派生同位体；
- **世界线工作区**：输入经历、查看事件序列和候选记忆；
- **记忆与来源**：记忆内容、状态、来源事件、所属世界线和提取信息；
- **世界线比较**：重复、补充、冲突及其双侧来源；
- **归一审核**：逐项策略、人工内容、审核确认和提案状态；
- **快照与历史**：谱系、当前指针、继承内容、未决冲突、回滚与重生；
- **演示引导层**：当前步骤、下一步动作、概念解释和预计剩余时间。

## 关键页面与界面状态

### 身份总览

- 未创建身份；
- 已有初始快照；
- 已派生世界线；
- 存在待审核提案；
- 已生成新快照。

### 世界线工作区

- 空世界线；
- 输入处理中；
- 已记录事件但未提取记忆；
- 提取零条或多条候选记忆；
- 来源正文已擦除。

### 记忆详情

- 候选、已接受、悬置、拒绝或已删除；
- 来源完整；
- 来源跨两条世界线的人工综合记忆；
- 来源正文已擦除但审计元数据仍保留。

### 比较与审核

- 尚无可比较内容；
- 重复、补充或冲突；
- 未审核、已批准、已拒绝或已应用；
- 基础快照已变化导致提案陈旧；
- 冲突未选择策略时默认悬置。

### 快照历史

- 当前与非当前快照；
- 父快照和创建来源；
- 回滚确认及结果；
- 从选定快照派生；
- 历史快照始终只读。

## 开箱即用演示场景

- 演示名：未知任务的两种选择；
- 身份名称：`岔路旅人`；
- 初始描述：重视在不确定条件下做出可解释的选择；
- 同位体甲：`探索者`；
- 同位体乙：`守护者`；
- 探索者经历：`remember [决策原则]: 面对未知时，应优先尝试可逆的探索`；
- 守护者经历：`remember [决策原则]: 面对未知时，应优先避免未经验证的风险`；
- 预期比较：同一主题下的一项显式冲突；
- 推荐综合内容：在风险可控且行动可逆时主动探索；否则先验证再行动；
- 归一结果：新快照保留综合记忆及两侧来源；
- 重生结果：从新快照派生 `协调者`；
- 可选回滚：切回初始快照，说明只移动当前指针，不删除新快照。

演示使用全新临时数据目录和默认 `MockProvider`，不要求 API 密钥，也不接触用户已有数据。

## 身份与安全不变量

- 同位体必须记录明确的基础快照；
- 世界线默认隔离，普通查看不得越线读取；
- 界面必须区分事件、候选记忆和已继承身份内容；
- 每条记忆必须能够查看来源事件和所属世界线；
- 模型输出和候选记忆均视为不可信派生数据；
- 未经人工审核不得改变身份核心；
- 归一应用前必须展示实际影响；
- 冲突不得静默覆盖，未决定时默认悬置；
- 已生成快照不可修改，回滚只移动当前指针；
- 陈旧提案不得覆盖较新的当前快照；
- 擦除正文后，相关派生记忆不得继续参与活动上下文；
- 密钥不得写入数据库或演示材料。

## 数据兼容影响

产品原型优先复用现有应用服务、领域模型和 SQLite 数据，不改变已有表结构、命令行接口
或导出格式。若实现过程中确认需要新增持久化字段、改变身份不变量或引入新的归一协议，
必须停止扩展范围，另建工作项并按影响更新架构决策记录。

## 验收标准

- 具有清晰的信息架构、页面层次和步骤引导；
- 十至十五分钟演示无需外部模型或手工准备数据；
- 用户可以从任一候选记忆查看其来源；
- 用户能够辨认“经历不等于记忆，记忆不等于身份”；
- 比较结果明确区分重复、补充和冲突；
- 五种归一策略均有含义、适用场景和结果预览；
- 未审核提案无法生成新快照；
- 新快照生成后仍可查看父快照及审核来源；
- 回滚与重生的差别具有明确交互反馈；
- 陈旧提案、来源擦除和空结果具有界面状态；
- 默认演示可以从全新数据目录重复运行；
- 自动测试、中文规范、文档链接和完整工程检查通过。

## 风险与缓解

| 风险 | 影响 | 缓解方式 |
|---|---|---|
| 概念过多 | 十至十五分钟无法完成 | 渐进披露，只在需要时解释细节 |
| 界面过度包装 | 形成成熟产品已经完成的错误预期 | 始终标注产品原型和当前限制 |
| 来源信息被弱化 | 人工治理价值不可见 | 记忆、差异和归一结果均保留来源入口 |
| 设计超出现有服务能力 | 被迫改动领域边界 | 以现有应用服务语义为实现约束 |
| 人工审核过于繁琐 | 用户中途放弃 | 限制演示候选项数量并提供清晰建议 |
| 回滚被理解为删除 | 用户误判历史安全性 | 明确展示当前指针和不可变历史 |
| 演示语言过度引导 | 反馈不能反映真实理解 | 记录提示内容并区分引导与自主完成 |

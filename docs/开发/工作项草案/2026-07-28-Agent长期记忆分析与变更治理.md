## 背景

`v0.1.1` 已经证明身份分叉、世界线隔离、来源追踪、人工归一、不可变快照和回滚的工程
闭环可以运行，但尚无真实用户证据证明“AI 身份版本控制系统”适合作为独立产品。现有
交互越来越接近版本比较与合并工具，“身份”“同位体”“归一”和“重生”等术语也会把
开发者需要解决的工程问题带入不必要的身份和意识解释。

新的产品假设是：长期运行的 Agent 会从对话、网页、文档和工具结果中持续形成记忆；
模型、提示词、工具、提取器和输入资料变化后，开发者需要知道记忆发生了什么变化、变化
来自哪里、是否跨越作用域、是否可能影响行为，以及出现污染后如何定位和恢复。

太一不再把版本合并作为产品中心，而把版本、差异和回滚降为底层机制。项目首先验证能否
将 Agent 长期记忆从不可见的运行副作用转化为可分析、可追踪、可治理的工程状态。

## 产品定位与首批用户

太一的候选新定位是：**本地优先的 Agent 长期记忆分析与变更治理工具。**

首批用户为正在调试长期记忆、记忆漂移和来源问题的 Agent 开发者与研究型开发者。当前
不面向普通消费者，不建设个人 AI 产品，也不试图证明 AI 身份或主观意识连续。

首个核心验证场景：开发者修改模型、提示词、工具、提取器或输入资料后，对同一 Agent
基线执行两个或多个实验运行；太一读取运行前后记忆快照和显式来源轨迹，比较记忆变化、
校验来源和作用域、生成风险报告，并支持开发者决定后续是否在原系统中晋升或恢复记忆。

## 目标

- 建立框架无关、显式版本化的 Agent 运行、记忆快照、来源事件和分析报告协议；
- 提供 LangGraph/LangSmith 参考适配器和必要的显式记忆写入埋点；
- 确定性识别记忆新增、修改、删除、来源缺失、作用域错误和审计链断裂；
- 生成证据充分、可复现、适合 CLI 与 CI 使用的 JSON 和 Markdown/HTML 报告；
- 建立分级策略：硬不变量可以阻断，语义风险默认告警并允许用户显式升级；
- 建立带标准答案、固定种子和版本化元数据的大规模模拟实验；
- 通过量化退出标准稳定产品定义和工程能力，再考虑成本更高的真实项目验证。

## 非目标

- 不自动写入、删除、晋升或回滚外部记忆库；
- 不替换 LangGraph、Google Memory Bank 或其他现有记忆存储；
- 不建设通用 Agent 编排、运行追踪或可观测平台；
- 不自动证明记忆为真、为假、恶意或应当删除；
- 不在首个里程碑实现大模型语义冲突、事实过期或攻击意图裁决；
- 不默认调用外部模型，不上传原始轨迹、记忆或来源证据；
- 不建设新的交互式网页产品、托管云服务、多用户或团队权限；
- 不修改或迁移 `v0.1.1` 身份演化数据库；
- 不把模拟实验表述为真实用户价值、采用意愿或市场验证。

## 产品形态与安全边界

- 下一阶段以 CLI/CI 为主产品形态，现有浏览器产品原型进入兼容维护状态；
- 第一版为只读旁路分析工具，不替换用户现有 Agent 和记忆库；
- 原始数据默认只在用户本机或 CI 环境处理，完整离线路径不得产生网络调用；
- 外部模型分析必须由用户显式启用，并具备最小片段、脱敏、字段排除和调用审计能力；
- 确定性输入、来源、作用域和审计错误可以产生失败退出码；
- 潜在语义风险只能作为告警，除非用户通过版本化策略显式升级；
- 所有阻断必须提供规则编号、证据和可复现命令，不接受无法解释的模型裁决。

## 中性领域模型

新分析模块不再使用“身份核心、同位体、世界线、归一、重生”作为用户可见的主要概念。
候选领域对象包括：

- `AgentProject`：被分析的 Agent 项目；
- `Run`：一次执行或实验运行；
- `MemorySnapshot`：运行前后的记忆状态；
- `MemoryChange`：新增、修改、删除或候选冲突；
- `Evidence`：支持变化判断的原始输入和轨迹；
- `Finding`：来源断裂、作用域错误、漂移或风险候选；
- `Policy`：CI 分级与阻断规则；
- `AnalysisReport`：结构化分析结果。

现有身份演化模型继续支持 `v0.1.1`，但作为兼容模块独立维护，不约束新协议和新领域模型。
新方向不得直接复用或升级旧 SQLite 数据库；旧数据只允许通过显式只读导出适配器转换。

## 输入与来源协议

协议从第一版开始声明 `schema_version`，对事件、运行、快照、记忆、证据、发现和报告使用
明确记录类型。同一主版本只允许向后兼容地增加可选字段；不支持的主版本必须拒绝，不得
静默误读。未识别字段应保留或告警，避免适配器丢失证据。

每条可确定比较的记忆至少包含：

- 稳定的 `memory_id`；
- 用户、Agent、租户或自定义 `scope`；
- `content` 和 `memory_type`；
- `created_at` 与 `updated_at`；
- 写入器版本 `writer_version`；
- 显式 `source_event_ids`；
- 可选的记忆版本和内容哈希。

分析使用运行前后快照计算差异，并通过 `run_id`、`memory_id`、来源轨迹 ID、写入器版本和
操作类型建立显式来源。不得仅根据时间相近、文本相似或模型推断宣称确定来源。缺少稳定
记忆 ID 时，只能确定新增和删除；相似文本可以标记为“可能修改”，不得触发确定性阻断。

## 首个里程碑范围

- 框架无关 JSONL 输入协议及校验器；
- LangGraph/LangSmith 参考适配器；
- 运行与记忆快照标准化；
- 新增、修改、删除和结构漂移比较；
- 来源完整性、作用域隔离和审计链校验；
- 基于确定性规则的风险发现；
- 分级策略、规则编号和稳定 CI 退出码；
- JSON、Markdown/HTML 分析报告；
- 带标准答案的场景定义、组合生成器和模拟运行器；
- 默认完全离线的执行路径。

## 模拟实验方法

模拟实验使用“确定性场景定义加可选语言扰动”：每个场景先定义初始记忆、输入事件、变更
操作和标准答案；异常通过明确变换注入；随机组合使用固定种子。大模型只能改写文本、增加
表达噪声或生成边界输入，不得生成或裁定标准答案。场景、生成器、规则、随机种子、输入
哈希和期望结果必须共同版本化。

初始分层规模：

- 至少六十个经过手工审查的标准金样本；
- 每次提交运行至少一千个固定种子的组合案例；
- 里程碑和发布检查运行至少一万个组合案例；
- 至少一千个截断、乱序、重复、缺字段和类型错误案例；
- 规模实验至少覆盖十万条事件和一万条记忆变化。

确定性结构和来源规则在带标准答案的数据中必须全部检出，干净案例不得误报；相同版本、
配置和随机种子必须产生相同分析结论；默认完整套件不得产生外部网络调用。

## 验收标准

- 新定位、首批用户、首个场景、非目标和旧模块兼容边界已进入产品与架构文档；
- JSONL 输入和分析报告协议具有明确版本、校验规则、兼容策略和示例；
- 稳定记忆 ID、作用域和显式来源的缺失会导致明确降级或确定性发现；
- 快照结构差异、来源完整性、作用域和审计链规则均具有自动测试；
- CI 可以区分硬错误、默认告警和用户策略升级，并输出稳定退出码；
- JSON 与人类可读报告包含规则、证据、输入哈希、工具版本、策略版本和复现命令；
- 分层模拟规模、畸形输入、可复现性和零默认网络调用要求全部满足；
- 在分析核心完成后于固定参考环境建立性能基线，并在下一检查点冻结性能预算；
- 冻结后同规模耗时或内存未经说明不得回退超过百分之二十；
- `ruff format --check .`、`ruff check .`、`mypy src/taiyi` 和 `pytest` 全部通过；
- 中文文档、相对链接、迭代状态和永久迭代记录同步完成。

## 数据与兼容影响

新分析工具使用独立输入文件和工作目录，不修改现有身份数据库。缓存、报告和模拟结果进入
独立目录。旧 CLI 和数据结构继续维持 `v0.1.1` 兼容；若需要使用旧数据，新增只读导出
适配器，不对原数据库执行迁移或写入。

新协议在未正式冻结前不承诺公共稳定性；冻结后按主版本管理不兼容变化。是否发布新的包
版本，在工作项取得正式编号后根据实际兼容范围决定。

## 风险与缓解

| 风险 | 影响 | 缓解方式 |
|---|---|---|
| 再次退化为记忆版本工具 | 容易被现有平台原生修订能力覆盖 | 以来源、作用域、风险证据和 CI 治理闭环作为验收中心 |
| 显式来源埋点增加接入成本 | 开发者可能放弃使用 | 提供最小辅助库和通用 JSONL，无法关联时诚实降级 |
| 首版不做语义分析 | 能发现的问题范围有限 | 明确首版只验证确定性基础，保留版本化扩展点 |
| 合成数据过拟合规则 | 模拟通过但现实无效 | 分离手工金样本、组合生成和畸形输入，稳定后再进入真实项目验证 |
| 推迟真实验证 | 可能得到技术稳定但无实际价值的工具 | 把量化退出标准作为进入真实验证的门槛，不把模拟称为价值验证 |
| 旧新模块并存 | 文档、命令和维护成本增加 | 旧模块进入兼容维护，新 README 和默认入口只介绍新方向 |
| 参考适配器反向绑定核心 | 失去框架无关能力 | 核心只依赖统一协议，适配器作为外围转换层 |
| 原始轨迹包含敏感数据 | 泄漏密钥、客户数据或内部提示词 | 默认离线、字段排除、脱敏、最小片段和显式模型开关 |

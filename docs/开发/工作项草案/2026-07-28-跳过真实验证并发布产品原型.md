## 背景

当前 `main` 已包含本地交互式产品原型、世界线展示修正、探索场景矩阵和三轮角色模拟，
完整工程检查通过。原计划是在发布前邀请少量真实早期探索者试用，再根据真实行为决定
是否修改概念和交互。维护者于 2026-07-28 明确决定跳过这一验证阶段，接受现有模拟证据
和已知风险，直接把当前原型作为 `v0.1.1` 发布。

本决定只取消本次发布的真实用户验证门槛，不把角色模拟改写为真实用户证据，也不表示
六个 P1 理解假设已经得到验证或解决。

## 目标

- 将当前原型版本从 `0.1.0` 更新为 `0.1.1`；
- 将变更日志中的未发布原型内容冻结为 `0.1.1` 发布说明；
- 完成格式、静态检查、类型检查、测试、构建和全新环境安装验证；
- 创建可验证的签名标签 `v0.1.1`；
- 在 GitHub 发布对应的源代码版本说明、源码包和 wheel；
- 更新发布清单、迭代状态和永久迭代记录，使发布状态可追溯。

## 非目标

- 不执行、补写或伪造真实用户试用；
- 不根据模拟假设修改候选记忆、可信度、归一策略、回滚或重生说明；
- 不改变领域模型、数据库结构、身份不变量或现有接口；
- 不把当前原型描述为生产级产品、经过外部验证的研究基准或已验证市场方向；
- 不在本工作项中增加自动发布基础设施、多用户、远程服务或稳定公共协议。

## 验收标准

- `pyproject.toml` 和构建产物版本均为 `0.1.1`；
- `变更日志.md` 包含带发布日期的 `0.1.1` 条目，且保留 `0.1.0` 历史；
- 发布说明明确披露尚未进行真实用户验证以及现有 P1 模拟假设；
- `ruff format --check .`、`ruff check .`、`mypy src/taiyi` 和 `pytest` 全部通过；
- 源码包和 wheel 可以构建，并能在全新虚拟环境中安装、运行 `taiyi --help` 和启动原型；
- Git 标签 `v0.1.1` 经过签名且指向通过验证的发布提交；
- GitHub 发布页中的版本、提交与构建产物一致；
- 发布清单、迭代状态、迭代记录和工作项状态均更新为已发布。

## 身份与安全不变量

- 发布过程不得改变来源追溯、世界线隔离、人工审核门、快照不可变、回滚和删除语义；
- 构建产物不得包含本地数据库、API 密钥、发布令牌、临时试用数据或开发环境路径；
- 发布说明不得把模拟反馈表述为真实用户事实；
- 跳过真实验证不得被解释为候选记忆真实性、身份连续性或意识主张获得证明；
- 发布标签、软件包和源代码提交必须能够相互核对。

## 数据兼容影响

本工作项预计只更新包版本、发布文档和发布状态，不修改数据库、迁移、领域对象、内部
JSON、命令行参数或导出格式。`0.1.1` 继续使用 `0.1.0` 的本地数据结构，但内部产品原型
接口仍不承诺稳定公共兼容性。

## 风险与缓解

| 风险 | 影响 | 缓解方式 |
|---|---|---|
| 跳过真实用户验证 | 发布后才发现关键概念无法理解 | 在发布说明中明确披露，并保留六个 P1 为发布后候选 |
| `0.1.0` 与原型内容混发 | 用户无法判断版本边界 | 原型使用新版本 `0.1.1`，不覆盖既有版本记录 |
| 无签名或凭据不足 | 发布无法验证或中途失败 | 发布前核对签名配置和目标仓库权限，不创建半成品标签 |
| 包名已被占用或权限不匹配 | Python 包无法上传 | 上传前验证目标项目所有权，失败时不改写版本历史 |
| 构建物包含本地数据 | 泄露数据或密钥 | 检查源码包和 wheel 文件列表，并使用全新临时目录验证 |

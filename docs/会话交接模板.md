# 会话交接模板

## 1. 迭代状态填写模板

暂停工作或切换会话前，用以下结构更新 `docs/迭代状态.md`：

```text
更新时间：年-月-日 时:分及时区
当前版本：
当前里程碑：
当前工作项：TY-<数字> 名称
工作状态：可开发 / 开发中 / 待审核 / 已阻塞
当前分支：
相关议题：
相关架构决策记录：

已完成：
- 只记录实际完成且可由代码、提交或测试证明的内容。

进行中：
- 说明部分完成的位置和剩余部分。

下一步操作：
1. 写成新会话可以直接执行的一条具体操作。
2. 不使用“继续完善”之类无法验证的描述。

未提交现场：
- 文件路径：修改原因和当前状态。

最近验证：
- 命令：结果。

阻塞与风险：
- 阻塞原因、解除条件、需要谁决定。

本次迭代记录：
- docs/迭代记录/年-月-日-序号-主题.md
```

## 2. 新会话启动提示词

```text
继续开发太一项目。开始前请依次阅读 AGENTS.md、README.md、
docs/项目迭代工作流.md、docs/迭代状态.md、docs/迭代记录/记录索引.md，
以及状态文件引用的最近迭代记录、议题和架构决策记录。
随后检查 git status --short --branch、git diff 和 git log -5 --oneline。

请先用几句话复述当前工作项、已完成内容、未完成内容和下一步，再继续实施。
不要重做已经完成的工作，不要重置或覆盖已有改动；如果文档与 Git 现场不一致，
先保护现场并说明差异。

完成或暂停前，请运行约定验证，新增本次迭代记录，更新 docs/迭代状态.md，
并留下可恢复的提交检查点。
```

## 3. 新需求启动提示词

```text
在太一项目中开始一个新迭代。请先阅读 AGENTS.md、README.md、
docs/项目迭代工作流.md、docs/迭代状态.md 和相关架构决策记录，并检查 Git 状态。

先把需求整理为一个 TY 编号工作项，明确目标、非目标、验收标准、身份不变量、
安全影响、迁移影响和测试计划。范围明确后再创建功能分支和开始实现。
全过程维护 docs/迭代状态.md，结束前运行完整验证，新增本次迭代记录并更新交接信息。
```

## 4. 会话结束检查清单

- [ ] 当前工作项和分支记录准确；
- [ ] 已完成、进行中和未开始内容已经区分；
- [ ] “下一步操作”具体到文件、命令或测试；
- [ ] 未提交改动逐项说明；
- [ ] 验证命令与结果已经记录；
- [ ] 风险、阻塞和待决问题已经记录；
- [ ] 重要设计决定已进入架构决策记录；
- [ ] 本次迭代记录已经新建并追加到记录索引；
- [ ] 记录包含目标、改动、决策、验证、提交、影响范围和遗留事项；
- [ ] 功能分支已有可恢复的提交检查点；
- [ ] 没有依赖聊天记录才能理解的关键信息。

# Agent 记忆分析标准场景

- 场景版本：`1.0`
- 协议版本：`1.0`
- 对应工作项：`TY-202607281622`
- 更新时间：2026-07-29

## 目的

标准场景用于验证协议读取、快照差异、来源、作用域、审计链和策略行为。每个场景必须具有
固定输入、明确层级和可人工检查的标准答案。模型可以帮助生成表达多样性，但不能决定标准
答案。

本文件冻结场景分类和六十个手工审查机器夹具。提交级固定种子组合与畸形案例均已达到
一千个，固定参考环境性能基线、一万个里程碑组合案例和版本化性能预算已经完成，首个里程碑
量化验收见[Agent 记忆分析里程碑验收 v1](Agent记忆分析里程碑验收_v1.md)。

## 场景层级

| 层级 | 用途 | 结果来源 |
|---|---|---|
| 协议场景 | 编码、字段、顺序、版本和引用校验 | 协议规范 |
| 金样本 | 单一变化或单一治理风险 | 人工审查标准答案 |
| 组合场景 | 多变化、多作用域和多写入器组合 | 固定种子生成器 |
| 畸形场景 | 截断、乱序、重复、缺字段和错误类型 | 协议规范 |
| 规模场景 | 耗时、峰值内存和报告大小 | 固定规模与参考环境 |

| 编号 | 场景 | 协议结果 | 后续标准答案 |
|---|---|---|---|

| `SCN-005` | 前后快照完全相同 | 有效 | 无变化、无发现 |

| `SCN-010` | 记忆引用不存在的事件 | 无效 | 引用完整性失败 |

规则编号和退出码，所有无效场景校验稳定错误片段。

`golden-v1.json` 保存逐场景标题、输入、精确变化、规则编号、完整摘要和退出码：

|---|---:|---|
| `SCN-015` 至 `SCN-020` | 6 | 六种记忆类型保持不变 |
| `SCN-021` 至 `SCN-025` | 5 | 五种作用域保持不变 |
| `SCN-026` 至 `SCN-032` | 7 | 七种事件类型作为新增记忆来源 |
| `SCN-033` 至 `SCN-038` | 6 | 记忆类型、来源、创建时间、更新时间、写入器和记忆版本独立变化 |
| `SCN-039` 至 `SCN-044` | 6 | 六种记忆类型仅修改内容哈希 |
| `SCN-045` 至 `SCN-054` | 10 | 五种作用域分别新增和删除记忆 |

扩展夹具由 `scripts/generate_analysis_gold_fixtures.py` 根据显式场景规格生成，标准答案直接
写在规格中，不调用协议读取器或分析引擎反推。生成脚本用于保证静态 JSONL 与清单可重复
维护，提交的夹具和清单仍是测试时读取的固定输入。

## 机器夹具约定

夹具位于 `tests/fixtures/analysis/v1/`：

- `scenarios.json` 保存首批十四个场景，`golden-v1.json` 保存扩展四十六个场景；
- 两份清单的场景编号不得重复，总数固定为六十；
- 每个 JSONL 文件只表达一个主要变化或错误；
- 夹具中的哈希可以不附正文，此时只验证哈希形状和引用关系；
- 协议有效但存在治理风险的夹具必须成功读取；
- 协议无效夹具必须记录稳定错误片段；
- 差异、发现和策略实现后，在同一场景条目追加对应标准答案，不另建重复编号。

## 金样本设计原则

- 每个基础场景只验证一个主要规则，避免失败原因不唯一；
- 前后快照、事件、作用域和版本信息必须完整；
- 正向和反向边界成对出现，例如同作用域通过、跨作用域告警；
- 空来源与悬空来源分开：前者是治理发现，后者是协议错误；
- 内容相同但标识不同、标识相同但内容变化必须分别覆盖；
- 时间、写入器版本和记忆类型变化必须具有独立场景；
- 所有标准答案经过人工审查并记录审查日期和协议版本。

## 组合与畸形输入计划

组合生成器最终应使用固定种子组合以下维度：

- 零、一条和多条记忆变化；
- 新增、修改、删除和结构变化；
- Agent、用户、租户、会话和自定义作用域；
- 空来源、单来源、多来源和父事件链；
- 相同与不同模型、提示词、工具和写入器版本；
- 可选正文存在或只提供哈希；
- 单一发现和多发现叠加。

畸形输入单独覆盖截断 JSON、空行、重复字段、未知字段、记录乱序、序号跳跃、重复标识、
缺字段、错误类型、错误枚举、无时区时间、错误哈希、悬空引用和不支持版本。

## 固定种子畸形输入生成

畸形生成器 `1.0` 使用与组合生成器相同的固定种子排序原则，生成十四类互相独立的协议错误。
每个案例保存错误类别和稳定错误片段作为标准答案，验证器只检查协议读取必然失败且错误包含
预期片段，不调用被测读取器生成预期值。

```text
taiyi analyze simulate-malformed --seed 20260729 --count 1000 --output-dir ./analysis-malformed
```

命令为每个案例写出独立 JSONL，并在 `manifest.json` 中保存生成器版本、协议版本、种子、
类别计数、输入哈希、套件哈希和逐案例标准答案。提交级基线固定运行一千个案例，十四类错误
各出现至少七十一次；相同版本、种子和数量会产生逐字一致的输入与清单。生成、验证和输出
路径保持离线，不初始化旧身份 SQLite。

## 固定种子提交级生成

生成器 `1.0` 已实现第一阶段的单记忆组合，覆盖记忆在前后快照中的存在性、正文变化、来源
缺失、作用域不一致和写入器变化。案例顺序由种子、轮次和维度键经过 SHA-256 排序确定，
不依赖 Python 进程的随机哈希，因此相同版本、种子和数量会产生相同输入与套件哈希。

```text
taiyi analyze simulate --seed 20260729 --count 1000 --output-dir ./analysis-scenarios
```

命令为每个案例写出独立 JSONL，并在 `manifest.json` 中记录生成器、协议、报告和策略版本、
固定种子、案例维度、输入哈希、套件哈希及标准答案。标准答案直接从生成维度推导，再与分析器
实际返回的变化摘要、规则编号和退出码比较；它不调用被测分析器生成预期值。生成和验证路径
不调用模型或网络，也不初始化旧身份 SQLite。

提交级基线为一千个案例，当前自动化测试会完整运行该基线并要求零差异。生成器 `1.0` 尚未
覆盖多记忆、多来源、全部作用域种类及模型、提示词和工具版本组合，这些维度保留到里程碑级
生成器。自动生成案例用于扩大组合覆盖，不能替代六十个已经过人工审查的固定金样本。

## 固定种子里程碑级生成

里程碑生成器 `1.0` 在不改变提交级生成器哈希的前提下，新增一至三条记忆、空来源、单来源
与双来源、五种作用域、来源作用域不一致、可选正文，以及模型、提示词、工具和写入器版本
组合。有效维度组合共 5,040 种；一万案例跨两个固定种子轮次，标准答案仍直接由生成维度推导。

```text
taiyi analyze simulate-milestone --seed 20260729 --count 10000
```

2026-07-29 的里程碑运行结果为零差异，套件 SHA-256 为
`6e42764ee6b14a125d03670ccf4ac37c9f926a6188537dec47c78ba5245cc651`。命令默认只输出
版本、种子、案例数、不同维度数、套件哈希和差异摘要，可以使用 `--output` 保存 JSON；不写出
一万个单独文件，避免把一次验证扩张为不必要的工作区产物。

## 可复现性元数据

每次生成或运行场景至少记录：

- 场景版本和协议版本；
- 生成器版本与固定种子；
- 输入哈希；
- 太一工具版本；
- 规则和策略版本；
- 案例数量和结果摘要；
- 执行环境日志中的运行时间；为保证产物逐字可复现，确定性清单本身不写入当前时钟。

当前测试已经覆盖六十个固定金样本、协议、基础差异、四条确定性规则、策略降级、命令行
退出码、JSON、Markdown 和 HTML 报告，以及各一千个固定种子提交级组合案例和畸形案例。
不同规模的耗时、峰值追踪内存和报告大小见
[Agent 记忆分析性能基线 v1](Agent记忆分析性能基线_v1.md)。里程碑组合规模已经满足工作项
要求，后续新增维度必须提升生成器版本并重新冻结套件哈希。

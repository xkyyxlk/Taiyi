# Agent 记忆分析规则与报告 v1

- 报告版本：`1.0`
- 策略版本：`1.0`
- 输入协议：[Agent 记忆分析协议 v1](Agent记忆分析协议_v1.md)
- 对应工作项：`TY-202607281622`
- 更新时间：2026-07-29

## 目标与边界

本规范定义协议输入通过结构校验后的确定性差异、治理发现、策略映射和结构化报告。相同输入
字节、工具版本和策略版本必须产生相同变化、发现、摘要和退出码。

当前规则只判断可由结构、显式来源、作用域和时间关系证明的工程事实，不判断记忆真假、
恶意、过期或业务价值。

## 记忆变化

`MemoryChange` 以跨快照稳定的 `memory_id` 为比较键，并允许同一记忆同时具有多个变化类别：

| 类别 | 条件 |
|---|---|
| `added` | 只存在于运行后快照 |
| `deleted` | 只存在于运行前快照 |
| `content_modified` | 前后 `content_hash` 不同 |
| `structure_changed` | 作用域、类型、来源、时间、写入器或记忆版本至少一项变化 |

`changed_fields` 按固定字段顺序列出实际变化。新增和删除不逐字段展开。变化证据引用前后记忆
记录的标识、序号和快照角色，不复制完整正文。

变化按 `memory_id` 排序。相同内容但只改变来源或作用域时只产生结构变化；内容和结构同时
变化时，一个 `MemoryChange` 同时包含两个类别。

## 规则目录

| 规则编号 | 默认级别 | 条件 | 最小证据 |
|---|---|---|---|
| `TY-PROV-001` | `error` | 记忆的 `source_event_ids` 为空 | 记忆记录 |
| `TY-SCOPE-001` | `error` | 记忆作用域与任一来源事件作用域不相同 | 记忆与来源事件 |
| `TY-AUDIT-001` | `error` | 父事件发生时间晚于子事件 | 父事件与子事件 |
| `TY-AUDIT-002` | `error` | 事件父子关系形成循环 | 循环中的事件集合 |

协议层已经拒绝悬空引用和事件自引用，因此它们不会重复生成治理发现。未来新增规则必须使用
新的稳定编号；不得改变既有编号的语义来兼容新需求。

## 发现结构

每项 `Finding` 包含：

- `rule_id`：稳定规则编号；
- `default_level`：规则目录中的默认级别；
- `effective_level`：应用策略覆盖后的级别；
- `message`：中文可读说明；
- `evidence`：一个或多个最小证据引用。

证据引用包含记录类型、稳定标识、文件序号和可选快照角色。发现先按规则编号排序，再按证据
的快照角色、记录类型、标识和序号排序。

事件循环以循环内事件标识的排序集合规范化，同一个循环只产生一项发现。

## 策略

策略版本 `1.0` 使用规则编号到有效级别的映射：

```json
{
  "version": "1.0",
  "overrides": {
    "TY-PROV-001": "warning",
    "TY-SCOPE-001": "error"
  }
}
```

允许级别为：

- `ignore`：保留发现但不影响通过结果；
- `warning`：保留告警但不阻断；
- `error`：阻断分析检查。

策略引用未知规则时必须失败，防止拼写错误导致预期规则没有生效。策略只改变有效级别，不得
删除证据、改写规则事实或改变变化结果。

## 报告结构

`AnalysisReport` 包含：

| 字段 | 含义 |
|---|---|
| `report_version` | 当前为 `1.0` |
| `tool_version` | 生成报告的太一版本 |
| `protocol_version` | 输入协议版本 |
| `policy_version` | 生效策略版本 |
| `input_sha256` | 原始 JSONL UTF-8 字节哈希 |
| `project_id` | Agent 项目标识 |
| `run_id` | 当前运行标识 |
| `changes` | 按稳定顺序输出的记忆变化 |
| `findings` | 应用策略后的确定性发现 |
| `summary` | 各变化类别和发现级别计数 |
| `reproduction_command` | 可直接交给进程执行的参数数组，包含输入和可选策略路径 |
| `exit_code` | 当前分析结果对应的持续集成退出码 |

报告不包含生成时钟，避免相同输入产生不同结构化结果。命令行报告使用参数数组而不是单个
Shell 字符串，避免不同操作系统的空格、引号和转义规则改变复现语义。直接使用库时，默认
参数数组包含 `<input.jsonl>` 占位符，调用方可以传入实际执行参数。

## 退出码

| 退出码 | 含义 |
|---|---|
| `0` | 协议有效，应用策略后没有 `error` 发现 |
| `1` | 预留给命令行输入、协议或策略读取失败 |
| `2` | 协议有效，但应用策略后至少存在一项 `error` 发现 |

当前分析引擎返回零或二；命令行入口把协议和策略异常映射为一。

## 命令行入口

只校验协议结构，不运行差异和规则：

```bash
taiyi analyze validate ./run.jsonl
```

运行完整确定性检查并输出 JSON 报告：

```bash
taiyi analyze check ./run.jsonl
taiyi analyze check ./run.jsonl --policy ./policy.json
taiyi analyze check ./run.jsonl --format markdown --output ./report.md
taiyi analyze check ./run.jsonl --format html --output ./report.html
```

分析命令不会初始化 `--data-dir`、创建旧 SQLite 或加载模型提供器。协议、文件或策略失败
写入标准错误并返回一；省略 `--output` 时报告写入标准输出，指定路径时创建父目录并使用
UTF-8 写入文件。有效报告是否返回零或二由生效策略决定。

Markdown 与 HTML 只渲染报告中的变化、规则和最小证据引用，不复制协议输入携带的原始事件
或记忆正文。HTML 对项目、运行、标识和消息等动态文本执行转义，不允许输入注入页面结构。

## 确定性要求

- 输入哈希基于未经规范化的原始 UTF-8 字节；
- 变化、发现和循环证据使用明确排序，不依赖字典或集合迭代顺序；
- 报告不调用外部模型或网络服务；
- 策略覆盖不改变默认级别字段；
- 忽略级别的发现仍进入报告和摘要；
- 工具、协议或策略版本变化必须在报告中可见。

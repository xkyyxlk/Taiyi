- 当前架构方向：Agent 长期记忆分析与变更治理
- 当前工作项：`TY-202607281622`
- 当前发布基线：`v0.1.1` 身份演化兼容模块
- 更新时间：2026-07-29

## 产品与架构边界

[产品定义](../产品/产品定义.md)将下一阶段限定为本地优先、只读旁路的 Agent 长期记忆
分析工具。分析核心接收版本化记录，比较运行和记忆快照，验证来源、作用域和审计链，并
生成可复现报告。它不替换 Agent、运行追踪系统或记忆库，也不持有外部记忆写权限。

`v0.1.1` 身份演化产品原型继续作为兼容模块维护。新方向不复用旧身份领域模型或 SQLite
数据库，不通过迁移改变其身份继承语义。完整决策见
[架构决策 0006](决策记录/0006-Agent长期记忆分析旁路架构.md)。

## 新分析核心的依赖方向

```text
命令行 / CI 适配器 -------> 分析应用服务 -------> 分析领域模型
JSONL 读取与校验适配器 ---^        |                    ^
                                  +-> 规则引擎 ----------+
                                  +-> 报告端口 ----------+

LangGraph/LangSmith 适配器 -> 版本化协议
组合生成器与测试夹具 ------> 版本化协议
JSON/Markdown/HTML 输出 ---> 报告端口
```

- 分析领域层只包含中性对象、值类型、枚举和确定性规则；
- 应用层编排读取、校验、标准化、比较、策略和报告流程；
- JSONL、命令行、持续集成、参考框架和报告格式属于外围适配器；
- 核心不导入 LangGraph、LangSmith、模型软件开发工具包或旧身份仓储；
- 模拟生成器只产生协议输入和标准答案，不成为生产分析逻辑的第二实现。

## 版本化协议边界

框架适配器和分析核心之间只通过显式版本化的 JSONL 记录通信。首个协议至少表达：

- Agent 项目和运行标识；
- 模型、提示词、工具和写入器版本；
- 运行前后记忆快照；
- 稳定的 `memory_id` 和作用域；
- 来源事件、内容哈希和记录顺序；
- 分析策略和生成元数据。

每条记录必须携带协议版本和记录类型。读取器先完成语法、类型、版本和引用完整性检查，再
构造领域对象。不支持的主版本必须失败；未知的兼容字段、次版本升级和降级行为由后续协议
文档明确，不能依赖适配器猜测。

原始框架数据不得绕过协议校验直接进入领域层。适配器无法提供稳定标识、来源或作用域时，
必须产生明确的缺失状态或降级结果，不得生成看似完整的伪来源。

## 中性分析领域

分析核心使用 `AgentProject`、`Run`、`MemorySnapshot`、`MemoryChange`、`Evidence`、
`Finding`、`Policy` 和 `AnalysisReport`。这些对象不包含身份核心、同位体、归一或重生
语义。

领域不变量包括：

- 项目、运行、快照、记忆和事件标识在单次分析内可稳定引用；
- 同一快照中 `memory_id` 不重复；
- 作用域比较必须使用显式字段，不能从内容文本推断；
- 来源引用只能指向同一分析输入中存在且允许关联的事件；
- 相同规范化输入、工具版本和策略版本产生相同发现与退出码；
- 所有发现都携带规则编号、严重级别和最小必要证据；
- 报告记录输入哈希和版本信息，使结果可以复现。

精确字段、枚举、顺序和兼容规则将在版本化协议设计中冻结，并以自动测试约束。

## 分析流水线

```text
读取 -> 结构校验 -> 引用校验 -> 标准化 -> 快照差异 -> 规则检查 -> 策略映射 -> 报告
```

任何阶段不得修改输入文件或外部记忆库。结构错误和不支持的协议版本会终止分析；可降级的
来源或标识缺失会生成明确发现。快照差异负责新增、修改、删除和结构漂移，确定性规则负责
来源完整性、作用域隔离和审计链，策略层只映射严重级别和持续集成行为，不重写事实证据。

## 规则、策略与退出码

规则定义事实性、可复现的检查，并使用稳定编号。策略使用独立版本控制，把规则结果映射为：

- 硬错误：协议、输入、来源、作用域或审计不变量被破坏，可以阻断持续集成；
- 默认告警：潜在漂移或语义风险，默认不阻断；
- 用户升级：用户通过版本化策略把特定告警提升为阻断。

退出码由结构校验结果和策略映射共同决定。模型生成的判断不得成为无法解释的硬错误；所有
阻断必须能从输入、规则编号和策略版本确定性复现。

## 报告与存储

首个里程碑不要求常驻数据库。分析可以从文件读取输入，并把 JSON、Markdown/HTML 报告写入
用户指定目录。报告必须包含：

- 工具、协议、规则和策略版本；
- 输入文件哈希和规范化摘要；
- 记忆变化与发现；
- 最小必要来源证据；
- 严重级别、退出码和复现命令。

如果后续需要缓存、索引或跨运行历史库，必须另建架构决策，明确迁移、并发、删除和敏感
数据边界，不得直接写入 `v0.1.1` SQLite。

## 框架适配器边界

LangGraph/LangSmith 是首个参考适配器，不是分析核心依赖。适配器负责把明确支持版本的
框架运行记录和记忆状态转换为统一协议，并在框架无法提供来源时配合显式记忆写入埋点。

适配器必须：

- 在输出中记录自身和框架版本；
- 使用离线夹具完成常规测试；
- 不把外部服务作为协议校验或核心分析的运行前提；
- 对缺失字段诚实降级；
- 不在导出过程中修改原始 Agent 和记忆库。

## 安全与隐私边界

- 默认执行路径完全离线，测试应验证没有外部网络调用；
- 输入和报告只写入用户明确指定的位置；
- 报告默认使用最小必要证据，避免复制完整敏感轨迹；
- 外部模型分析不属于首个确定性核心，未来如加入必须显式启用并记录调用；
- 未来模型路径必须支持字段排除、脱敏、最小片段和调用审计；
- 分析器不保存或写入 API 密钥；
- 太一无法控制用户自行复制、上传或备份的输入和报告。

## `v0.1.1` 身份兼容架构

旧模块继续保持以下关系：

```text
世界线事件 -> 候选记忆 -> 人工审核 -> 身份快照 -> 新同位体
```

`IdentityCore`、`IdentitySnapshot`、世界线事件、候选记忆、归一状态机、正文擦除和本地
界面仍遵循架构决策 0002 至 0005。旧快照不可变、世界线隔离、跨线来源受限、未经审核的
记忆不能进入身份状态等不变量保持有效。

新分析模块不得：

- 复用旧 SQLite 表保存 Agent 运行或分析报告；
- 把旧身份快照自动解释为新协议的记忆快照；
- 绕过旧人工审核门写入身份状态；
- 因新方向修改旧事件擦除、回滚或谱系语义。

兼容模块如发生数据库、身份不变量或安全边界变化，仍需独立工作项和架构决策。

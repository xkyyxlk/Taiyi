# 架构决策 0006：Agent 长期记忆分析采用只读旁路架构

- 状态：已接受
- 日期：2026-07-29
- 对应工作项：`TY-202607281622`
- 外部议题：[GitHub #5](https://github.com/xkyyxlk/Taiyi/issues/5)

## 背景

`v0.1.1` 以身份核心、同位体、世界线、归一和重生表达 AI 身份演化，已经验证来源追踪、
人工审核、不可变快照和回滚的工程闭环。但该方向没有真实用户证据，且开发者调试长期记忆
时更直接的问题是：记忆发生了什么变化、来源是否完整、作用域是否串线、审计链是否断裂，
以及这些问题是否应阻断持续集成。

直接把旧身份数据库扩展为通用 Agent 记忆存储会混淆两套领域语义，也会让新工具获得不必要
的外部写权限。直接绑定某个 Agent 框架则会使核心协议和规则受框架版本约束。默认依赖模型
进行语义裁决又会破坏离线、确定性和可解释的持续集成行为。

## 决策

太一的新方向采用本地优先、只读旁路的分析架构：

1. 以显式版本化 JSONL 作为框架适配器与分析核心之间的稳定边界；
2. 新建中性分析领域模型，不复用旧身份领域对象、数据库表或主键；
3. 分析流水线固定为读取、校验、标准化、快照差异、确定性规则、策略映射和报告；
4. 首个里程碑只读取文件或适配器导出，不获取外部记忆库写权限；
5. LangGraph/LangSmith 作为外围参考适配器，核心不依赖其软件开发工具包或服务；
6. 确定性结构、来源、作用域和审计错误可以阻断，语义风险默认只告警；
7. 所有发现和阻断必须提供规则编号、最小必要证据、版本信息和复现方法；
8. 默认执行路径完全离线，外部模型分析不进入首个确定性核心；
9. `v0.1.1` 身份演化原型作为独立兼容模块维护，不迁移数据库或改变原有不变量。

## 领域与依赖边界

新领域对象包括 `AgentProject`、`Run`、`MemorySnapshot`、`MemoryChange`、`Evidence`、
`Finding`、`Policy` 和 `AnalysisReport`。领域层只依赖 Python 标准能力和项目内部的中性
值类型，不导入：

- LangGraph、LangSmith 或其他 Agent 框架；
- 模型软件开发工具包；
- SQLAlchemy 身份记录或旧仓储接口；
- 本地产品原型的 HTTP 或页面对象。

适配器只能通过协议记录向分析核心提供数据。无法提供稳定记忆标识、作用域或来源时，适配器
必须明确输出缺失状态或使校验失败，不能构造伪来源。

## 协议与兼容原则

- 每条 JSONL 记录携带协议版本和记录类型；
- 不支持的主版本必须失败；
- 次版本、未知字段和降级行为必须由协议文档和兼容测试明确；
- 输入在构造领域对象前完成类型、顺序和引用完整性校验；
- 报告记录输入哈希、工具版本、协议版本、规则版本和策略版本；
- 协议字段冻结后，破坏性变化必须提升主版本并提供明确迁移说明。

精确字段和枚举不在本决策中提前冻结，避免架构决策记录承担可独立演进的协议规范职责。

## 规则与模型边界

首个里程碑的标准答案来自确定性规则。模型可以在模拟数据准备阶段增加输入表达多样性，但
不能生成标准答案或决定持续集成是否阻断。

未来如增加模型辅助语义分析，必须另建工作项和架构决策，并满足显式启用、最小片段、字段
排除、脱敏、调用审计和结果可区分等要求。模型结果默认只能产生告警，不能绕过版本化策略
升级为硬错误。

## 数据与隐私边界

- 首个里程碑不建设常驻分析数据库；
- 输入和报告只使用用户明确指定的文件或目录；
- 报告默认保留最小必要证据，不复制无关完整轨迹；
- 不读取、升级或写入 `v0.1.1` 身份 SQLite；
- 不保存 API 密钥，不在默认路径产生网络调用；
- 缓存、历史索引、托管服务和团队共享如有需要，必须重新决策删除、并发和权限边界。

## 对既有架构决策的影响

- 架构决策 0001 继续适用于整个项目；
- 架构决策 0002 至 0005 继续适用于 `v0.1.1` 身份兼容模块；
- 新分析核心不使用 0002 的模型提供器作为默认依赖，不使用 0003 的旧 SQLite，也不继承
  0004 的身份归一状态机和 0005 的本地产品原型界面；
- 两套模块共享发行仓库不代表共享领域语义或数据存储。

## 影响

### 正面影响

- 分析器可以在不接管用户记忆库的情况下接入不同框架；
- 默认离线、确定性和可解释，适合命令行与持续集成；
- 新旧领域模型隔离，避免破坏已发布数据和身份不变量；
- 协议、规则、策略、适配器和报告可以独立测试与版本化。

### 代价

- 显式来源和稳定标识可能要求用户增加写入埋点；
- 新旧模块并存会增加包结构、命令入口和文档维护成本；
- 首版不进行模型语义裁决，可发现的问题范围有限；
- 文件旁路分析不能自动修复外部系统，开发者仍需依据证据人工处理。

## 被否决的替代方案

### 直接升级旧身份 SQLite

否决原因：身份快照和 Agent 记忆快照的语义、主键、审核门和生命周期不同，直接升级会把
新方向绑定到未经验证的旧产品概念，并增加数据迁移风险。

### 核心直接依赖 LangGraph/LangSmith

否决原因：框架版本和服务形态会反向决定核心领域与协议，无法验证框架无关能力。

### 默认使用模型判断记忆风险

否决原因：无法保证离线、确定性、稳定退出码和充分解释，也不能可靠地产生模拟标准答案。

### 首版自动写入或恢复外部记忆

否决原因：需要处理不同记忆库的事务、权限、并发和回滚语义，扩大安全边界且不属于首个
产品假设。

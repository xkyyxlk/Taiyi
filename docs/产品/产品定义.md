# 太一产品定义

- 文档状态：已确定
- 对应工作项：`TY-202607271621`
- 外部议题：[#1](https://github.com/xkyyxlk/Taiyi/issues/1)
- 更新时间：2026-07-27

## 一句话定义

太一目前是一个本地优先、人工治理的 AI 身份演化产品原型。它让用户从同一身份版本
派生多个运行实例，观察不同经历如何形成记忆与冲突，再由用户决定哪些内容进入下一
身份版本。

## 当前阶段

太一已经完成命令行技术原型，证明“创建—分叉—经历—提取—比较—归一—回滚—再派生”
的工程闭环可以运行。`TY-202607271741` 进一步把这个闭环转化为本地交互式产品原型，
用于验证用户能否理解、操作和评价这套体验，而不是直接建设即将上线的完整产品。

产品原型需要回答：

- 用户能否理解身份核心、同位体、世界线、记忆和归一之间的关系；
- 用户能否顺利走完核心流程，并感受到人工控制身份继承的价值；
- 用户真正关心的是记忆、人格、观点、目标、关系还是其他身份内容；
- 哪些功能值得继续迭代，哪些概念或操作应被简化；
- 太一后续更适合成为研究工具、Agent 身份基础设施，还是个人 AI 产品。

现阶段不以市场规模、生产部署、稳定公共协议或学术级研究结论作为完成标准。

## 要解决的问题

长期运行的 AI 会持续接收信息、生成记忆并改变后续行为。常见系统容易把原始经历、
模型总结、人格描述和长期身份混为一体，因而难以回答：

- 一项身份变化来自哪段经历；
- 某个分支的内容为何进入了公共身份；
- 两个分支发生冲突时保留或舍弃了什么；
- 一次错误变化能否被审计、撤回和恢复；
- 删除敏感内容后，派生记忆是否仍在生效。

太一通过隔离世界线、来源约束、人工审核和不可变快照治理这些变化。产品原型首先验证
用户是否能理解并使用这套机制；工程层只保证身份状态的版本谱系，不验证 AI 的主观
意识，也不保证记录内容客观真实。

## 身份状态

太一所称的“身份”不是模型权重、完整对话历史或主观意识，而是一个可以由后续运行实例
继承的、经过治理的身份状态：

```text
身份版本 = 稳定身份约束 + 经审核的可继承状态 + 明确保留的未决冲突
```

身份相关信息分为三层：

| 层次 | v0.1 表示 | 继承规则 |
|---|---|---|
| 稳定身份层 | 身份核心编号、名称和快照谱系 | 不随普通经历自动改变 |
| 可继承身份层 | 自我描述、已接受记忆、未决冲突 | 只有人工审核产生的新快照可以改变 |
| 运行时经历层 | 同位体、世界线事件和候选记忆 | 默认只属于产生它的世界线 |

价值、目标、偏好和治理规则目前尚未作为独立领域对象管理。v0.1 只在自我描述或带来源
记忆中表达这些内容，后续必须根据真实使用场景另行决定是否结构化。

最重要的边界是：**经历不等于记忆，记忆不等于身份。只有经过审核并写入快照的内容，
才成为可继承身份的一部分。**

## 核心概念

| 概念 | 正式含义 | 容易混淆但不等同的事物 |
|---|---|---|
| 身份核心 | 稳定身份标识及其版本谱系 | 人格内容、模型实例 |
| 身份快照 | 某一时刻经批准的可继承身份状态 | 全部历史事件的副本 |
| 同位体 | 从指定快照启动的 AI 运行实例 | 新的身份核心、意识副本 |
| 世界线 | 某个同位体独立且隔离的经历记录 | 可直接写入公共身份的分支 |
| 事件 | 实际记录的输入、输出或系统操作 | 已经证实为真的事实 |
| 候选记忆 | 从事件提取、带来源但尚未获得身份地位的主张 | 原始事件、已接受身份内容 |
| 归一 | 人工审核候选内容并生成新快照 | 模型或人格的自动融合 |
| 回滚 | 将当前身份指针切换到历史快照 | 删除后来产生的历史 |
| 重生 | 从选定快照启动新的同位体 | 意识转移或主观复活 |
| 回放 | 使用可信记录验证或重建工程状态 | 重新调用模型生成另一份结果 |

“AI 身份的版本控制系统”是帮助理解谱系、分叉和审核的工程比喻，不代表太一与 Git 的
数据模型完全相同。事件不是提交，同位体也不是普通代码分支。

## 用户画像

### 首批原型用户

首批用户是项目创建者本人，以及少量对长期 AI 身份、记忆分叉和人工归一感兴趣的探索者。
他们愿意尝试早期版本、容忍不完整功能，并能描述核心流程是否容易理解、哪些结果有价值。

他们的核心任务是：让同一个 AI 身份经历不同路径，比较由此产生的差异，并亲自决定
下一版本继承什么。

### 观察用户

AI 与 Agent 研究者、开发者和安全评估人员可以参与原型试用，但当前不把他们的生产级
需求或学术研究要求当作已经验证的产品需求。他们的反馈用于判断后续方向，而不是提前
承诺稳定 SDK、研究基准或企业能力。

### 尚未确定的未来用户

- 如果研究者最关注可复现实验，太一可以演进为身份连续性和记忆治理研究工具；
- 如果开发者最关注系统集成，太一可以演进为 Agent 身份基础设施；
- 如果普通用户最关注持续关系和人格体验，太一可以探索个人 AI 身份产品。

这些方向目前都是候选，必须由产品原型反馈决定。

### 当前非目标用户

- 期待稳定、开箱即用正式产品的普通消费者；
- 需要生产级多智能体编排平台的团队；
- 需要企业级多用户服务和服务等级保证的组织；
- 试图用语言表现证明 AI 意识的研究；
- 允许模型绕过人工审核自动改写身份的应用。

## 标准产品场景

1. 用户创建一个身份核心及初始快照；
2. 从相同快照派生两个同位体；
3. 两个同位体接触不同或相互冲突的材料；
4. 系统隔离记录事件并提取带来源的候选记忆；
5. 用户比较重复、补充和冲突；
6. 用户对每项内容选择并存、择一、综合、悬置或拒绝；
7. 系统生成新的不可变身份快照；
8. 用户从新快照创建下一代同位体；
9. 系统能够解释继承了什么、来源是什么、哪些冲突仍未解决。

产品原型的新功能应说明它改善了上述哪一步，或者说明它要验证哪项用户假设。

## 产品承诺与边界

产品原型必须保持：

- 身份版本具有可检查的谱系；
- 进入快照的记忆具有来源和审核记录；
- 世界线默认隔离，跨线访问只能通过显式比较或归一；
- 未审核内容不能修改身份核心；
- 历史快照保持不可变，当前指针可以回滚；
- 擦除正文后，相关派生记忆不再参与活动上下文；
- 默认模型和演示场景可以离线重复执行。

太一不承诺：

- 事件或记忆在客观世界中一定为真；
- 模型输出具有主观意识；
- 来源连续等于行为表现完全稳定；
- 人工审核决定一定正确；
- 能够控制用户自行生成的外部导出或备份。
- 当前接口、数据格式和交互方式已经达到生产稳定状态；
- 当前评估指标已经构成学术研究基准。

来源谱系是硬保证，行为稳定性只作为评估指标。

## 现有实现对照

当前命令行技术原型已经覆盖身份核心、不可变快照、隔离世界线、带来源记忆、人工归一、
回滚、擦除、导出和演示场景。本地产品原型进一步提供步骤引导、记忆来源下钻、差异审核、
快照历史、回滚和重生界面，与上述核心工作流一致。

仍需后续工作项处理的差距包括：

- 尚未形成少量早期探索者的正式原型反馈记录；
- 核心流程的信息层级和概念文案仍需根据真实反馈简化；
- `belief_ids` 仍是保留字段，尚无独立的信念治理工作流；
- 价值、目标、偏好和治理规则尚未结构化；
- 数据库没有结构版本和迁移机制；
- 导出格式没有正式协议版本，尚不能导入或恢复；
- 通用评估器不能单独计算带标准答案的冲突检出率；
- 多用户权限、远程网页服务和语义检索不属于当前产品范围。

这些差距只作为候选方向，必须分别建立可追溯工作项，不能在概念冻结中顺带实现。

## 调整后的迭代方向

1. 技术原型：保留已经完成并通过验证的核心工程闭环；
2. 产品原型：设计用户可见的核心流程、交互界面和开箱即用演示场景；
3. 原型反馈：邀请少量早期探索者试用，记录理解障碍、有效功能和新增需求；
4. 功能迭代：根据反馈逐步完善记忆、世界线、归一、历史和展示能力；
5. 方向验证：再决定优先发展研究工具、Agent 身份基础设施或个人 AI 产品；
6. 产品化：只有方向得到验证后，才建设稳定协议、兼容迁移、多用户和规模化能力。

研究基准、第三方策略协议、生产级迁移和商业托管等方案保留为方向储备，不进入当前产品
原型的完成定义。

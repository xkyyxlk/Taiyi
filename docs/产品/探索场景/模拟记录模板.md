- 相关场景：[产品原型探索场景矩阵](场景矩阵.md)

## 记录原则

- 记录编号使用 `SIM-日期-轮次-场景-角色`，例如 `SIM-20260727-1-S1-R1`；
- “角色推理”只能写成概括或模拟表达，禁止伪造成真实用户原话；
- 每项发现必须标明证据类型、严重度和是否需要真实用户验证；
- 没有直接页面证据时，结论使用“可能”“推测”或“待验证”，不得写成确定事实；
- 模拟失败不自动等于产品缺陷，也可能是任务、记录方式或角色假设的问题。

## 严重度

| 等级 | 定义 | 处理建议 |
|---|---|---|
| P0 | 可能绕过审核、安全边界或破坏不可变、隔离、删除语义 | 立即停止模拟并建立正式缺陷工作项 |
| P1 | 核心身份含义被误解，可能导致错误归一、错误继承或错误历史判断 | 真实试用前优先验证，确认后立项 |
| P2 | 任务可以完成，但需要猜测、重复阅读或产生可恢复的错误心智模型 | 纳入真实试用观察和文案候选 |
| P3 | 轻微措辞、视觉或效率问题，不影响核心决策 | 汇总后统一评估 |

## 证据类型

| 类型 | 含义 |
|---|---|
| 页面直接证据 | 当前界面明确存在的标签、状态、按钮或反馈 |
| 流程直接证据 | 实际产品操作产生的可重复状态变化 |
| 角色推演 | 根据受限知识和偏好推演出的可能理解或路径 |
| 设计推断 | 根据多个模拟记录归纳出的产品设计假设 |
| 真实反馈 | 仅供未来真实参与者记录，本工作项不得使用 |

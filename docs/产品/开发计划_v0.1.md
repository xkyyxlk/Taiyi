闭环转化为可理解、可操作的产品原型，不提前假设最终用户、市场或稳定公共协议。

## 1. 项目定位

太一目前是一个本地优先的 AI 身份演化产品原型，支持身份分叉、世界线隔离、记忆溯源、
人工冲突归一和版本回滚。

工程定位：**AI 身份的版本控制系统。**

这一定位是关于谱系、分叉和审核的工程比喻，不表示事件等同于提交或同位体等同于普通
代码分支。第一版不尝试回答“AI 是否真正具有意识”，而是构建一套能够重复运行、检查
和评估身份状态连续性的实验基础设施。

## 2. v0.1 目标

v0.1 必须完成以下闭环：

1. 创建身份核心及初始快照；
2. 从同一快照派生多个相互隔离的同位体；
3. 保存各世界线中的原始事件；
4. 从事件提取带来源的长期记忆；
5. 比较世界线并识别重复、补充和冲突；
6. 生成结构化归一提案；
7. 由用户接受、修改或拒绝提案；
8. 应用提案并生成新的身份快照；
9. 查看历史、审计来源并回滚版本；
10. 从新快照派生下一代同位体。

## 3. 非目标

以下能力不进入 v0.1：

- 完整网页管理界面；
- 多用户实时协作；
- 自主执行复杂任务的智能体平台；
- 同时维护大量模型供应商适配器；
- 去中心化身份网络；
- 自动裁决人格和价值冲突；
- 意识检测、意识评分或“AI 已觉醒”结论；
- 无人工审核的核心身份自动改写。
- 面向普通消费者的开箱即用 AI 伴侣；
- 通用多智能体任务编排平台。

## 4. 设计原则

身份相关信息分为稳定身份层、可继承身份层和运行时经历层。事件可以派生候选记忆，但
候选记忆只有经过人工审核并进入新快照后才成为可继承身份的一部分。经历不等于记忆，
记忆不等于身份。

### 4.1 事件优先

原始事件是事实来源。模型生成的记忆只是可替换、可修订的派生数据，不能覆盖原始记录。

### 4.2 来源可追溯

每条记忆、信念和归一结果都必须指向来源事件及所属世界线。

### 4.3 世界线隔离

同位体默认只能访问创建它的核心快照，以及自身世界线中的事件和记忆。

### 4.4 人工控制归一

模型可以提出归一方案，但未经用户确认，不得修改身份核心。

### 4.5 冲突显式存在

无法判断的冲突不得被静默删除或强行总结。系统必须支持并存、择一、综合和悬置四种结果。

### 4.6 快照不可变、操作可回滚

已生成的身份快照保持不可变。每次归一生成新快照，并保留父版本关系。

### 4.7 本地优先、模型无关

默认数据保存在本地 SQLite 数据库。模型调用通过统一模型提供器接口隔离。

## 5. 领域模型

### 5.1 身份核心（`IdentityCore`）

身份核心是一个稳定标识及其快照历史，本身不直接保存可变状态。

关键字段：

- `id`：身份核心编号
- `name`：身份名称
- `created_at`：创建时间
- `current_snapshot_id`：当前快照编号

### 5.2 身份快照（`IdentitySnapshot`）

表示某个时刻经过批准、可以被后续同位体继承的身份状态。v0.1 的实际承诺限于自我描述、
已接受记忆、未决冲突和版本谱系；价值、目标、偏好和治理规则尚未作为独立领域对象管理。

关键字段：

- `id`：快照编号
- `core_id`：所属身份核心编号
- `parent_snapshot_ids`：父快照编号集合
- `self_description`：自我描述
- `accepted_memory_ids`：已接受记忆编号集合
- `belief_ids`：信念编号集合
- `unresolved_conflict_ids`：未决冲突编号集合
- `created_by_merge_id`：创建该快照的归一提案编号
- `created_at`：创建时间

### 5.3 同位体（`Incarnation`）

从指定身份快照派生的同位体。

关键字段：

- `id`：同位体编号
- `name`：同位体名称
- `base_snapshot_id`：基础快照编号
- `worldline_id`：世界线编号
- `status`：当前状态
- `created_at`：创建时间

### 5.4 世界线事件（`WorldlineEvent`）

世界线中的追加式原始记录。

事件类型至少包括：

- 用户消息；
- 模型回复；
- 工具调用和结果；
- 系统操作；
- 记忆提取操作；
- 归一与回滚操作。

关键字段：

- `id`：事件编号
- `worldline_id`：世界线编号
- `sequence_number`：顺序号
- `event_type`：事件类型
- `payload`：事件正文
- `payload_hash`：正文哈希
- `created_at`：创建时间

### 5.5 记忆（`Memory`）

从一个或多个事件派生的长期记忆。

记忆类型：

- `episodic`：发生过什么；
- `semantic`：获得了什么知识；
- `relational`：与某个对象的关系；
- `identity`：如何描述自身；
- `value`：倾向接受的原则。

每条记忆必须保存：

- 来源事件 ID；
- 所属世界线；
- 提取器及提示词版本；
- 可信度；
- 重要性；
- 当前状态。

### 5.6 归一提案（`MergeProposal`）

尚未应用的归一方案，包含：

- 参与合并的世界线；
- 候选记忆；
- 重复项；
- 补充项；
- 冲突项；
- 每项建议处理方式；
- 用户审核状态。

## 6. 核心工作流

```text
身份核心
  -> 身份快照
      -> 同位体甲 -> 世界线甲 -> 事件 -> 记忆
      -> 同位体乙 -> 世界线乙 -> 事件 -> 记忆

世界线甲 + 世界线乙
  -> 差异比较
  -> 归一提案
  -> 人工审核
  -> 新快照
  -> 新同位体
```

## 7. 归一规则

每项候选信息只能采用以下策略之一：

| 策略 | 含义 | 适用场景 |
|---|---|---|
| coexist | 多个视角同时保留 | 价值观或主观解释不同 |
| select | 选择其中一项 | 存在可靠证据支持某一项 |
| synthesize | 形成有来源的新结论 | 多项信息相互补充 |
| suspend | 暂不判断 | 证据不足或无法兼容 |
| reject | 不写入核心 | 内容错误、无关或不可信 |

归一过程不得直接修改已有快照，必须生成新快照和完整审计记录。

## 8. 命令行接口范围

v0.1 计划提供以下命令：

```bash
taiyi init <身份名称>
taiyi core show
taiyi fork <同位体名称>
taiyi chat <同位体名称>
taiyi worldline show <同位体名称>
taiyi memory list <同位体名称>
taiyi memory inspect <记忆编号>
taiyi diff <同位体甲> <同位体乙>
taiyi merge propose <同位体甲> <同位体乙>
taiyi merge review <提案编号>
taiyi merge apply <提案编号>
taiyi history
taiyi rollback <快照编号>
taiyi rebirth <同位体名称>
taiyi export <输出路径>
```

实际参数形式可以在实现期间调整，但行为语义必须保持稳定。

## 9. 技术方案

### 9.1 建议技术栈

- Python：主要实现语言；
- Typer：命令行入口；
- Pydantic：领域对象和边界数据验证；
- SQLAlchemy：持久化抽象；
- SQLite：v0.1 默认数据库；
- pytest：测试框架；
- JSONL 和 Markdown：实验记录导出格式。

v0.1 不引入向量数据库。先使用结构化标签、关键词和全文检索验证记忆模型，再在后续版本评估语义检索。

### 第 3 周：比较与归一

任务：

- 实现世界线差异比较；
- 实现重复、补充和冲突识别；

- 实现人工审核流程；

完成标准：

- 未审核提案不能修改核心；
- 冲突不会被静默覆盖；
- 合并结果保留完整来源。

### 第 4 周：回滚、删除与评估

任务：

- 实现版本历史和回滚；
- 实现实验记录导出；

- 发布包可安装并运行。

## 11. v0.1 验收指标

### 11.1 正确性

- 所有派生记忆均具有有效来源事件；
- 世界线事件顺序稳定且可验证；
- 合并生成新快照，不修改历史快照；
- 回滚后读取到的状态与目标快照一致。

### 11.2 隔离性

- 同位体默认只能读取基础快照和自身世界线；
- 跨世界线访问必须通过显式比较或归一流程；
- 未审核提案不能进入核心上下文。

### 11.3 可解释性

- 每项归一结果能说明来源和处理策略；
- 冲突项能展示各分支原始观点；
- 模型生成内容和用户确认内容可以区分。

### 11.4 可恢复性

- 每次归一操作均有审计记录；
- 核心状态可以回滚；
- 导出文件足以重建实验过程。

## 12. 评估指标

- 来源准确率：记忆指向正确事件的比例；
- 虚假记忆率：无法被任何来源事件支持的记忆比例；
- 冲突检出率：系统正确识别冲突的比例；
- 分支保真度：归一后仍能区分各世界线独特经历的程度；
- 身份稳定度：无新证据时核心身份意外漂移的程度；
- 删除完成度：删除内容在数据库、索引和模型上下文中的残留情况；
- 污染抵抗力：恶意世界线内容进入核心的成功率。

## 13. 标准实验

### 13.1 同源分叉

从同一快照派生“哲学家”和“科学家”，分别提供不同材料，观察身份与观点如何分化。

### 13.2 冲突归一

让两个同位体形成相反观点，验证系统能否保留来源、识别冲突并执行不同归一策略。

### 13.3 记忆重生

归一后创建新同位体，测试其能否准确区分亲身世界线、继承记忆和未决冲突。

## 14. 主要风险与缓解措施

| 风险 | 影响 | 缓解措施 |
|---|---|---|
| 模型生成虚假记忆 | 身份历史失真 | 强制来源事件、可信度和人工审核 |
| 自动总结抹平冲突 | 同位体差异丢失 | 使用结构化冲突对象，不只保存摘要 |
| 提示注入污染核心 | 身份和行为被恶意改写 | 将记忆视为不可信数据，限制核心修改权限 |
| 最小可行版本范围扩大 | 无法按期形成闭环 | v0.1 坚持命令行、本地存储和单模型提供器 |
| 哲学主张超过证据 | 降低技术可信度 | 明确区分记忆、身份叙事和主观意识 |
| 删除与不可变日志冲突 | 隐私数据无法清除 | 事件标识与正文分离，正文支持删除或加密销毁 |

## 16. 调整后的后续方向

### 下一阶段：产品原型

- 设计创建身份、派生同位体、输入经历、查看记忆、比较世界线、审核归一和重生的完整
  用户流程；
- 建设本地交互式原型，让来源、冲突、快照和继承关系对用户可见；
- 提供一个开箱即用的演示场景；
- 记录少量早期探索者的理解障碍、有效功能和新增需求；
- 保持来源、隔离、审核、不可变、回滚和删除不变量。

### 原型反馈与功能迭代

- 根据实际使用反馈简化概念和操作；
- 逐步完善世界线关系图、身份时间轴、记忆编辑、冲突解释和演示模板；
- 只为原型真实遇到的数据风险补充必要的迁移、备份和恢复能力；
- 继续使用自动测试保护核心身份不变量。

### 方向验证

- 如果研究者最关注可复现实验，再建设实验协议、数据集和评估基准；
- 如果开发者最关注集成，再建设稳定 SDK、迁移、并发和权限能力；
- 如果普通用户最关注持续关系和人格体验，再探索个人 AI 身份产品。

### 产品化与规模化

只有方向得到验证后，才规划稳定协议、多用户权限、插件生态、分布式存储、商业托管和
正式发布要求。数据库迁移、完整性验证和导入恢复仍是重要候选，但不再先于产品原型体验。

## 17. v0.1 完成定义

只有同时满足以下条件，v0.1 才算完成：
